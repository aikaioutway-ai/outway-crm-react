# CRM Messages API

Модуль «Сообщения»: уведомления CRM и переписка сотрудников.

Деплой с `verify_jwt: false`, как `task-api`: сотрудники входят через `employee-login` и присылают подписанную сессию в заголовке `x-employee-session`. Функция проверяет подпись, срок и что сотрудник активен — на каждом запросе. Таблицы `v2_messages` и `v2_message_reads` закрыты от браузера (RLS, без политик для anon/authenticated); ключ service_role не покидает функцию.

Группы задаются только в `access.ts`, CRM получает их отсюда:

- `notifications` — «Уведомления», только чтение; видят начальник логистики, директор, гендиректор и админ;
- `all` — «Все»;
- `dept:*` — отделы. Руководство (админ, гендиректор, директор) видит и пишет во всех.

Действия: `channels` (группы с непрочитанными), `messages` (по 50, `before` — листать назад), `send`, `read`, `notify-overdue`.

`notify-overdue` раз в день (по Бишкеку) кладёт в «Уведомления» сводку просроченных новых заявок по школам. Его вызывает CRM, когда сотрудник из руководства открывает её; `dedupe_key` не даёт создать второе уведомление за день. Правило просрочки в `overdue.ts` повторяет `src/modules/families/requestWorkflow.ts`, школы — `schools.ts` (копия из `task-api`).

Нужны миграции `crm_messages`, `transfer_marks_and_comments` и `transfer_mark_at`.
