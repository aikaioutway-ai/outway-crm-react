# AGENTS.md

Инструкции для Codex при работе с репозиторием OutWay CRM.

## Обязательное чтение перед задачей

Перед любой задачей:

1. Полностью прочитать `CLAUDE.md`.
2. Прочитать `docs/project-memory.md`, если файл существует.
3. Прочитать профильную документацию затрагиваемого модуля или процесса из `docs/`.
4. Если продолжается незавершённая задача и существует `HANDOFF.md`, прочитать его и считать текущим состоянием передачи между Claude Code и Codex.

## Источник правил

`CLAUDE.md` — главный источник общих правил проекта: архитектуры, безопасности, работы с Supabase, UX/UI, производительности, переиспользования, тестирования, документации, legacy-кода и защиты секретов.

Не копировать эти правила сюда. Если правило в `CLAUDE.md` явно относится только к Claude как продукту, применять его к Codex по смыслу.

`CODING_RULES.md` разрешено использовать только как дополнительный исторический контекст. Он может быть устаревшим и не имеет приоритета над `CLAUDE.md`. При конфликте инструкций использовать следующий приоритет:

1. прямое указание пользователя в текущей задаче;
2. более строгие ограничения из `AGENTS.md`;
3. `CLAUDE.md`;
4. `CODING_RULES.md` как дополнительный исторический контекст.

## Git: более строгие правила Codex

- Локальные изменения и проверки разрешены только в рамках явно поставленной задачи.
- `commit`, `push`, `merge`, слияние PR и deploy выполнять только после явного разрешения пользователя.
- Никогда автоматически не выполнять `force push`, `git reset --hard`, переписывание истории и другие destructive Git-команды.
- Перед изменениями проверять `git status`, сохранять существующие изменения пользователя и не включать их в свою работу без явного поручения.

Эти правила заменяют для Codex любые указания `CLAUDE.md` об автоматическом commit или push.

## Supabase и production

- Read-only изучение схемы, функций и данных для диагностики разрешено.
- Изменение production-данных, схемы, RLS, migrations, Edge Functions, ENV, secrets или deploy выполнять только после отдельного явного подтверждения пользователя.
- Destructive-действия не выполнять автоматически.
- Не раскрывать секреты, токены, пароли, приватные ключи, приватные URL или реальные значения ENV в коде, документации, логах и ответах.

## Передача задач

При передаче работы между Claude Code и Codex опираться на репозиторий и актуальный `HANDOFF.md`, если он существует, а не на предположения из прошлых чатов. Перед продолжением проверять текущую ветку, `git status`, последний commit, выполненные проверки и явно отмеченные незавершённые действия.
